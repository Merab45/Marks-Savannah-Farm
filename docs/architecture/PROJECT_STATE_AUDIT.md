# Marks Savannah Farm — Project State Audit

**Status:** Architecture baseline, ready for owner review  
**As of:** 2026-11-20  
**Scope:** Repository and implementation evidence only. No production cloud projects or backend were inspected or created.

## Executive summary

The repository is a static vanilla HTML/CSS/JavaScript project containing three application areas: the public farm website, two overlapping customer application/dashboard implementations, and a Herdbook farm-record workspace. The PWA manifest and one root service worker are present. No package manifest, build system, API server, central database, or cloud integration was found in the repository search.

The public site and customer flows can be continued in place. Herdbook is a meaningful existing foundation, but it is currently a browser-local prototype and is not private through authentication or server authorization. The most important continuity decision is to keep the PWA as the customer experience, consolidate the two customer dashboards without deleting either route, and evolve Herdbook rather than replacing it.

## Verified entry points and routes

| Area | Entry points | Existing pages/screens |
|---|---|---|
| Public website | index.html | Homepage, About, Products & Services, Contact, Gallery, Blog, Auctions, Shop, Privacy Policy, Terms & Conditions |
| Customer application | app.html | Splash, onboarding, sign-in, sign-up, then dashboard views generated by farm-home.js |
| Customer dashboard | customer-account.html | Home, Marketplace, Auctions, Saved, More, Profile; separate sign-in and create-account pages |
| Farm workspace | herdbook.html | Overview, My animals, Marketplace, Sales & records |

The customer-account route redirects unsigned users to sign-in.html. The PWA manifest has start_url ./app.html and scope ./, and JS/site.js registers the single root service-worker.js. The root service worker currently includes herdbook.html in its static shell cache list.

## Technology and code ownership observed

- The frontend uses static HTML, a shared CSS file, and plain JavaScript. No framework or build configuration was found in the project root.
- CSS/site.css contains styling for public pages and app/workspace areas.
- JS/site.js is page-aware: it contains contact, onboarding/auth, Herdbook, customer dashboard, and public-auction logic behind page checks.
- JS/farm-home.js renders the app.html customer dashboard. JS/auction-core.js is used by the customer app, customer dashboard, and public auction page. JS/auction-page.js owns public auction-page rendering. JS/commerce.js supports shop behavior and product/service page links.
- Assets are shared by the existing website and customer experience; some are also referenced by Herdbook.
- No API URL, database SDK, server route, SQL migration, or provider configuration was found. Searches covered project HTML, JavaScript, manifest, service worker, README and root configuration files. This is evidence about this repository, not proof that no external service exists outside it.

The app screens are not all equivalent. customer-account.html is closer to the established customer dashboard mockup and exposes profile, order-history, and support sections. app.html is the actual PWA start route and supplies splash/onboarding/auth plus a separate dashboard implementation. farm-home.js has product and auction detail flows that should be retained when the customer dashboard is consolidated.

## Security and exposure findings

1. Herdbook has a robots noindex directive, but noindex is not access control. The HTML is in the root static site and service-worker precache list. Anyone who knows its URL can request it.
2. Customer account, saved item, order preview, cart, auction state, and Herdbook data are browser-local. They do not form a central record and can be read or edited by the browser profile owner.
3. Public visibility is not currently governed by a server-side approval boundary. Future public APIs must use an explicit public projection of approved farm data, not expose raw animal or health records.
4. No payment processor, social OAuth integration, password recovery service, or shared-bid backend was found.

## Recommendations and implementation boundary

- Preserve all current routes and UI while building the backend foundation.
- Keep public website and customer PWA logically connected; use one customer identity provider and a canonical dashboard experience.
- Use Herdbook as the staff product foundation, keeping its existing animal and sales workflows. Add real access control before importing confidential operational data.
- Do not cache private records or report a local draft as a completed order, payment, or bid.
- The selected backend recommendation and migration plan are documented in PLATFORM_ARCHITECTURE.md and the linked decision records.
